# 함정 모음 — 실제로 부딪힌 것

2026년 9월 기준입니다. 어드민이 바뀌면 틀릴 수 있습니다.

## 공통

### 반복 접속은 막힌다
- 짧은 시간에 목록을 끝까지 스크롤하거나, 같은 화면을 여러 번 열면 **"비정상 동작" · "잠시 이용 제한"** 이 뜹니다.
- 로그인을 짧은 시간에 여러 번 하면 **계정 보호조치**가 걸립니다. 해제는 계정 주인이 직접 요청해야 합니다.
- 그래서: 미답변 탭이 있으면 그것부터, 스크롤은 상한을 두고, 동작 사이 1.5~3초 쉬고,
  시험은 **하루에 한 곳 한 건**.

### 로그인은 사람이
- 코드가 아이디·비밀번호를 넣으면 봇으로 봅니다.
- 한 곳은 **로그인은 통과시키고 그 뒤 데이터만 막습니다.** 화면은 멀쩡한데 리뷰가 안 옵니다.
  그래서 로그인 성공은 **데이터가 실제로 오는지**로 판단합니다.
- 로그인 화면을 여러 탭에서 열면 "이미 처리되었거나 만료된 요청" 이 뜹니다. 한 번 새로 불러오면 됩니다.

### 입력칸은 React
- `value` 만 바꾸면 화면엔 보여도 앱은 모릅니다. 네이티브 setter 로 넣고 `input` 이벤트를 보냅니다.
  (`scripts/fill.ts` 의 `FILL_BOX`)

### 엉뚱한 칸에 채우기
- 어드민 화면에 **"의견을 남겨주세요"** 같은 다른 입력칸이 늘 떠 있는 곳이 있습니다.
  "화면에 입력칸이 하나뿐이면 답글칸" 으로 여기면 거기에 채웁니다.
- 그래서 입력칸은 **그 리뷰 카드 안에서만** 찾고, 채운 뒤 카드에 단서가 그대로 있는지 다시 확인합니다.

### 여는 버튼 = 올리는 버튼?
- 배민·쿠팡은 여는 버튼 이름에도 「등록」이 들어갑니다(예: 사장님 댓글 등록하기).
- 네이버는 여는 버튼 후보에 「답글 등록」을 넣으면 **올리는 버튼을 누를 수 있습니다.**
- 그래서 `scripts/platforms.ts` 에 플랫폼마다 **절대 누르지 않을 글자(neverClick)** 를 둡니다.

### 버튼은 그 카드 안에서만
- 화면 전체에서 "답글" 버튼을 찾으면 맨 위 리뷰에 씁니다.
- 단서가 든 가장 작은 조각에서 시작해, 답글 버튼이 들어올 때까지만 부모로 올라갑니다.

## 배달의민족

- 셀프서비스는 자바스크립트 앱이라 주소만 불러오면 빈 껍데기입니다.
- 리뷰 API 요청에 **서명**이 붙어서, 우리가 새로 만든 요청은 거절됩니다.
  어드민이 보내는 요청의 개수·쪽수 값만 바꿔치기합니다. **기간 값은 건드리면 거절**됩니다.
- 리뷰번호가 화면에 그대로 나와서, 채우기 단서로 가장 확실합니다.
- "파트너님에게만 보이는 리뷰" 는 손님에게 안 보입니다. 답글을 달아도 공개되지 않으니 건너뛰어도 됩니다.

## 쿠팡이츠

- 봇 차단이 강합니다. 브라우저 밖에서 API 를 부르면 막힙니다. **어드민 페이지 안에서 같은 출처 fetch** 로 부릅니다.
- 리뷰 API 는 한 번에 받는 개수를 바꾸면 거절될 수 있습니다. 어드민이 쓰는 값을 그대로 씁니다.
- 창 없는 모드를 봇으로 봅니다. 창을 화면 밖에 띄웁니다.
- 어드민 화면
  - 기본 조회기간이 **오늘**이라 목록이 거의 비어 있습니다. 기간을 고르고 **「선택」** 으로 확정한 뒤 **「조회」** 를 눌러야 목록이 바뀝니다.
    리뷰 날짜에 맞춰 가장 좁은 기간부터 고르면 빨리 찾습니다.
  - 무한 스크롤이 아니라 **페이지 넘김**입니다. 현재 페이지 버튼에 active 표시가 붙습니다.
  - **스크립트 클릭(`element.click()`)을 무시**합니다. 답글 열기와 페이지 넘기기는 좌표로 진짜 클릭합니다
    (`platforms.ts` 의 `realClick: true`).
  - 답글 입력칸이 리뷰 줄 **바로 아래 줄**에 따로 열립니다.
- 이름을 **가려서**(김*윤) 보여줘서 동명이인이 생깁니다. 별점만 남긴 리뷰가 많아 본문도 단서가 못 됩니다.
  가린 이름 · 리뷰 날짜 · "N회 주문" · 메뉴 앞부분이 **모두 맞는 줄이 딱 하나일 때만** 채웁니다.
- 답글 수정 규칙: 답글칸에 "작성일 기준 14일이 지나면 수정이 불가합니다" 안내가 보인 적이 있습니다.
  14일 안에는 고칠 수 있을 가능성이 큽니다 — **직접 확인하세요.**

## 네이버 스마트플레이스

- 로그인은 **일반 네이버 로그인**입니다. 가게를 관리하는 네이버 아이디로 합니다.
- 방문자 리뷰라 **별점 없이 글만** 있는 리뷰가 많습니다. 평균 계산에서 뺍니다.
- 리뷰 목록 조회를 **GraphQL(POST)** 로 합니다. 읽기 전용 강제는 mutation 이 아닌 조회만 통과시킵니다.
- 창 없는 모드를 봇으로 봅니다. 창을 화면 밖에 띄웁니다.
- 답글칸 열기
  - 네이버 자체 **AI 초안**이 붙은 리뷰는 「AI가 답글 초안을 작성했어요」를 펼친 뒤 「이 답글 수정」을 눌러야 입력칸이 나옵니다.
  - AI 초안이 없는 리뷰는 「답글 쓰기」 한 번이면 됩니다.
  - 입력칸 아래에 **「등록」 · 「닫기」** 가 있습니다. 시험이면 「닫기」.
  - 최소 15자, 최대 500자입니다.

## 맥

### 바탕화면에 두면 밤 수집이 조용히 죽는다
- macOS 는 예약 실행(launchd)이 바탕화면 · 문서 · 다운로드 폴더를 읽지 못하게 막습니다.
  로그에는 "Operation not permitted" 나 "Resource deadlock avoided" 가 남고, 알림은 안 옵니다.
- 바탕화면이 iCloud 와 동기화되면 파일이 실제로는 내려받아져 있지 않아 옮기기도 멈춥니다.
- **프로젝트는 홈 폴더 바로 아래에** 둡니다 (예: `~/review-onetouch`).

## 크롬

### https 웹에서 localhost 도우미를 부르면 조용히 끊긴다
- 크롬은 공개 사이트가 내 컴퓨터(localhost)를 부를 때, 사전 요청에
  `Access-Control-Allow-Private-Network: true` 응답을 요구합니다.
- 없으면 요청이 나가기도 전에 끊기고, 웹에는 "도우미가 꺼져 있다" 고만 보입니다.

## 초안

- **홀과 배달을 구분**하지 않으면, 매장에 온 손님에게 "따로 챙겨 보내드립니다" 가 나갑니다.
- 주문 메뉴로 먼저 맞추면, "국물이 깊다" 고 쓴 리뷰에 다른 메뉴 이야기를 합니다. **리뷰 내용이 먼저**입니다.
- 가게 사실(재료, 산지, 조리법)은 **사장님이 확인해 준 것만** 씁니다. 그럴듯하게 지어낸 한 줄이 가장 위험합니다.
- 손님 질문에는 답을 지어내지 말고 자리를 비워둡니다.
- "맛나요", "최고죠" 같은 말끝을 질문으로 착각하지 않게 합니다.
