# AI 에게 시키는 순서

**첫 프롬프트(준비 · 설문 · PRD) → (0단계는 들어 있음) → 1 → 2 → 3 → 4 → 5**

- 앞 단계가 끝나야 다음으로 갑니다. 하루에 다 하지 마세요.
- 0~3단계까지 하고 **며칠 초안을 읽어본 뒤** 4 · 5단계로 가세요.
  초안이 마음에 안 드는데 5단계로 가면, 마음에 안 드는 글을 어드민에 채우는 기계가 됩니다.
- 매 단계 프롬프트 맨 앞에 **공통 규칙**을 붙입니다. 매번 말해야 AI 가 잊지 않습니다.
- 아래 1~5단계는 배민 · 쿠팡이츠 · 네이버를 쓰는 경우의 예시입니다.
  PRD 에 다른 플랫폼이 나왔으면 이름을 바꿔서 시키세요.

---

## 첫 프롬프트 — 준비부터 기획서까지 (STIC)

짧게 붙여넣고, 세부 기획은 AI 가 **선택지로 물어서(AskUserQuestion)** 채우게 합니다.
준비(설치 · 로그인 창 · 가게 번호)는 AI 가 알아서 합니다. 사장님은 고르고, 창에서 비밀번호만 입력합니다.
끝나면 `docs/PRD.md` 가 생깁니다.

```
【 S · 상황 】
- 나는 (가게 이름) 사장이야. 배달앱 · 네이버에 리뷰가 흩어져 있고, 답글은 지금 내가 하나씩 달아.
- 이 폴더는 리뷰 원터치 스타터 키트야. 나는 코딩을 잘 몰라.

【 T · 할 일 】
1. 내 상황을 AskUserQuestion 으로 물어봐 — 한 번에 1~4개, 번호 보기로 고를 수 있게.
   (쓰는 플랫폼 · 맥/윈도우 · 목적 우선순위 · 리뷰 양 · 지금 답글 방식과 걸리는 시간 · 예산)
2. 내 답에 맞게 준비는 네가 알아서 해줘.
   - 빠진 게 있으면 설치하고, 에이전트 브라우저가 필요하면 다운로드 페이지를 열어줘.
   - 쓰는 플랫폼의 로그인 창을 하나씩 띄워줘. 비밀번호는 내가 창에서 입력할게.
   - 가게 번호 같은 설정은 로그인된 화면에서 네가 찾아서 채워줘.
3. 내 말투(최근 답글 3개)와 절대 자동화하면 안 되는 것까지 더 물어본 뒤, 기획서(PRD)를 써줘.

【 I · 의도 】
- 모은 고객이 떠나지 않게 빠짐없이 답하고, 리뷰를 데이터로 쓰고, 관리 시간을 줄이려는 거야.
- 가게마다 상황이 달라서, 만들기 전에 내 상황에 맞는 범위와 순서부터 정하고 싶어.

【 C · 주의할 점 】
- 아직 구현하지 마. 이번엔 준비와 PRD까지만.
- 아이디 · 비밀번호는 묻지도, 입력하지도 마. 로그인은 내가 창에서 직접 해.
- 로그인 창은 한 번에 하나씩. "보호조치" · "비정상 동작" 이 뜨면 바로 멈추고 알려줘.
- 답글 등록 버튼은 내가 누른다. PRD 의 "안 만들 것"에 넣어줘.
- 모르는 건 지어내지 말고 "확인 필요"로. 돈이 드는 건 먼저 물어봐.
```

## 공통 규칙 — 매 단계 프롬프트 맨 앞에

```
【 공통 규칙 — 항상 지켜 】

docs/PRD.md 와 CLAUDE.md 를 먼저 읽고 그 범위 안에서만 만들어.

1. 어드민에 답글을 실제로 등록하는 기능은 만들지 마. 등록 버튼은 내가 누른다.
   나중에 만들더라도 두 겹 잠금(명령 옵션 + 환경변수 둘 다)이 있어야만 동작하게 해.

2. 로그인은 내가 창에서 직접 한다. 아이디·비밀번호를 코드가 대신 입력하지 마.
   플랫폼들이 자동 입력을 봇으로 본다. 로그인 상태는 scripts/login.ts 가 만드는
   영구 프로필(data/sessions/)을 다시 써.

3. 로그인 성공은 화면이 아니라 데이터로 판단해. 화면이 떠도 리뷰 데이터 요청이 막혀 있으면 실패다.

4. 어드민의 내용은 절대 바꾸지 마. 수집기는 scripts/lib/browser.ts 의 enforceReadOnly 를 켜.
   팝업은 닫기(X)로만 없애. 확인·동의·설정 버튼은 누르지 마.

5. "비정상 동작" · "이용 제한" · "보호조치" 같은 문구가 뜨면 즉시 멈추고 나한테 알려. 다시 시도하지 마.
   플랫폼 접속은 한 번에 한 건, 간격을 두고. 여러 번 연달아 시험하지 마.

6. 한 번에 다 만들지 마. 이번 단계에 적힌 것까지만.
   만들기 전에 내 의도를 이해했는지 먼저 설명해.
```

## 0단계 — 뼈대 (이미 들어 있음)

AI 에게 "뼈대 화면 보여줘" 라고 하면 뜨는 가짜 리뷰 화면이 0단계 결과물입니다. 넘어가도 됩니다.
**처음부터 직접 만들어 보고 싶다면** `app/` 을 지우고 아래를 시키세요.

```
(공통 규칙 붙여넣기)

【 0단계 — 뼈대 】
리뷰 답글을 도와주는 웹페이지를 만들 거야. 이번에는 화면 하나만.

- 가짜 리뷰 5건이 카드로 뜬다. 데이터는 sample/reviews.json 한 파일.
- 카드에 플랫폼 · 별점 · 날짜 · 주문 메뉴 · 리뷰 내용 · 답글 초안 칸.
- 초안 칸은 처음부터 펼쳐져 있고 고칠 수 있다.
- "승인" 버튼은 지금은 눌러도 표시만 바뀐다.
- 위에 탭: 리뷰 답글달기 / 인사이트 / 설정. 지금은 첫 탭만 내용이 있다.
- 폰에서도 읽혀야 해. DB 는 아직 만들지 마.
```

**끝났는지 확인**: 가짜 리뷰 5건 · 펼쳐진 초안 칸 · 승인을 누르면 표시가 바뀐다.

## 1단계 — 한 곳만 뚫기

세 곳을 한꺼번에 하지 않습니다. PRD 에서 **리뷰가 제일 많은 곳 하나**부터. 아래는 배민 예시입니다.

```
(공통 규칙 붙여넣기)

【 1단계 — 첫 플랫폼 리뷰 가져오기 (배민) 】

- 먼저 배민 로그인 창을 띄워줘. 로그인은 내가 창에서 하고, 끝나면 알려줄게.
- scripts/collect-baemin.ts 를 만들어. scripts/lib/browser.ts 의 openPersistent 로
  배민 어드민 리뷰 페이지(scripts/platforms.ts 의 reviewsUrl)를 열어.
- 화면 글자를 긁지 말고, 어드민이 스스로 받아오는 리뷰 API 응답을 가로채 JSON 으로 받아.
  어떤 API 인지는 먼저 네트워크를 보고 알아내서 나한테 설명해.
- 배민은 요청에 서명이 붙어서 우리가 새로 보내면 거절된다. 어드민이 보내는 요청의
  개수·쪽수 값만 바꿔치기해. 기간 값은 건드리지 마.
- 저장: data/baemin-reviews.json. 한 건에 플랫폼, 리뷰번호, 별점, 내용, 주문 메뉴,
  작성일, 작성자 표시명, 사장님 답글(있으면), 답글 작성일.
- 증분: INCREMENTAL=1 이면 저장된 것 이후 새 리뷰만.
- enforceReadOnly 를 켜. 막히면 data/screenshots/ 에 스크린샷을 남겨.
```

**끝났는지 확인**: `data/baemin-reviews.json` 에 내 가게 리뷰가 있고, 사장님 답글이 붙은 건도 있다.

## 2단계 — 나머지 플랫폼 + 중앙 DB

```
(공통 규칙 붙여넣기)

【 2단계 — 나머지 플랫폼 수집 + 중앙 DB 】

쿠팡이츠 (scripts/collect-coupang.ts):
- 봇 차단이 강하다. 브라우저 밖에서 부르면 전부 막힌다. 어드민 페이지 안에서 같은 출처 fetch 로 불러.
- 한 번에 받는 개수를 바꾸면 거절될 수 있다. 어드민이 쓰는 값을 그대로 써.
- 로그인 성공은 매장 정보 API 가 정상 응답하는지로 판단해. 막혔으면
  "쿠팡이 이 브라우저를 막았다, 다시 로그인하라" 고 알리고 멈춰.

네이버 스마트플레이스 (scripts/collect-naver.ts):
- 방문자 리뷰다. 별점 없이 글만 있는 리뷰가 많다. 평균 계산에서 빼.
- 창 없는 모드를 봇으로 보니, 창을 화면 밖에 띄워(openPersistent 의 offscreen).
- 네이버는 조회도 POST(GraphQL)로 한다. enforceReadOnly 는 mutation 이 아닌 조회만 통과시킨다.

중앙 DB:
- 무료로 시작할 수 있는 Postgres 를 추천해줘. 가입과 연결 문자열 복사는 내가 할게.
  DATABASE_URL 은 .env.local 에만. 돈이 드는지 먼저 알려줘.
- 테이블: 리뷰 · 답글(초안) · 말투. 같은 플랫폼 + 리뷰번호는 덮어써서 몇 번 돌려도 중복이 안 쌓이게.
- scripts/ingest.ts: 수집 JSON 을 DB 에 넣는다. 리뷰 내용을 보고 불만 종류를 규칙으로 붙여
  (맛·품질 / 양·가격 / 배달·포장 / 응대 / 위생 / 기타). LLM 없이.
- 웹페이지가 sample/reviews.json 대신 DB 를 읽게 바꿔.
```

**끝났는지 확인**: 웹페이지에 모든 플랫폼 실제 리뷰가 뜬다. 사장님이 예전에 단 답글이 DB 에 수백 건 이상 있다.
이게 없으면 3단계가 의미가 없습니다 — **기존 답글이 곧 말투 교본**입니다.

## 3단계 — 내 말투로 초안

```
(공통 규칙 붙여넣기)

【 3단계 — 내 말투로 초안 쓰기 】

scripts/analyze-voice.ts:
- 플랫폼별로 내 기존 답글을 읽어 뽑아: 호칭(손님/고객님/OO님), 종결어미, 첫인사, 끝인사,
  평균 길이, 자주 쓰는 이모지, 자주 쓰는 문장(횟수 포함). DB 에 저장.

초안 조립:
- LLM 을 쓰지 말고, 말투 분석에서 나온 내 실제 문구를 재료로 조립해. 그래야 내 말 그대로 나온다.
- 리뷰 내용을 먼저 보고 손님이 무엇을 짚었는지 골라. 주문 메뉴로 먼저 맞추지 마.
- 홀과 배달을 구분해. 네이버는 방문 리뷰라 기본이 홀, 배달앱은 배달.
  다만 본문에 "매장 · 가서 · 방문" 이 있으면 홀, "배달 · 포장 · 시켰" 가 있으면 배달.
  방문 손님에게 배달 이야기가 나가면 안 된다.
- 손님이 질문했으면 그 자리를 비워둬: 【여기에 답을 적어주세요 — 손님이 물어본 내용입니다】
  지어내지 마.
- 별점 1~2점은 사과가 먼저다. 설명은 그다음. 불만이 없는 3점에 사과하지 마.
- 내가 알려주지 않은 가게 사실(재료 산지, 조리법 등)은 쓰지 마.

scripts/draft-all.ts: 답글 없는 리뷰 전부에 초안을 만든다. DB 에는 묶어서 넣어.
웹페이지: 초안이 펼쳐져 보이고, 고칠 수 있고, "초안 다시 쓰기" 버튼이 있다.
```

**끝났는지 확인**: 초안 20건을 읽어보세요. "내가 쓴 것 같다" 싶으면 통과.
아니면 무엇이 어색한지 AI 에게 말해주세요. 여기서 며칠 써도 됩니다.

## 4단계 — 밤에 혼자 돌게

```
(공통 규칙 붙여넣기)

【 4단계 — 밤 배치 】

scripts/auto-collect.ts:
- 플랫폼 수집을 차례로. 하나가 실패해도 나머지는 계속. 모두 실패하면 적재는 건너뛴다.
- 그다음 ingest → analyze-voice → draft-all.
- 새 리뷰만 받는다 (최근 14일 정도).
- 끝나면 알림을 한 번 띄워. 실패한 플랫폼이 있으면 "확인 필요 — OO 로그인이 풀렸을 수 있습니다".
  조용히 실패하면 나는 리뷰가 없는 줄 안다.
- 로그는 data/logs/ 에 날짜별로. 매 실행 결과(플랫폼, 성공 여부, 새 리뷰 수)를 DB 에도 남겨서
  웹에서 볼 수 있게.

예약 등록 — 내 컴퓨터(PRD 참고) 쪽만 만들어:
- 맥: launchd. 등록 전에 예약 실행이 이 폴더를 읽을 수 있는지 확인해.
  바탕화면 · 문서 · 다운로드 안이면 막힌다. 그러면 등록하지 말고 폴더를 옮기라고 안내해.
- 윈도우: 작업 스케줄러. 컴퓨터가 잠들어 있으면 못 도니 "절전 해제하여 실행" 을 켜.
- 하루 한 번이면 충분하다. 자주 돌리면 플랫폼이 막는다.
```

**끝났는지 확인**: 밤에 혼자 돌고, 아침에 알림이 와 있고, 웹에 새 리뷰와 초안이 있다.

## 5단계 — 승인하면 답글칸까지

가장 위험한 단계입니다. 공통 규칙 1번을 다시 읽으세요.
채우는 코드는 **`scripts/fill.ts` 에 이미 있습니다.** 이 단계는 웹의 승인 버튼과 이어붙이는 일입니다.

먼저 AI 에게 이렇게 말해 한 건만 시험합니다.

> 에이전트 브라우저가 붙는지 확인하고, 최근 리뷰 한 건만 답글칸에 채워줘. 등록은 누르지 마.

그다음 시킵니다.

```
(공통 규칙 붙여넣기)

【 5단계 — 승인 → 어드민 답글칸 채우기 】

웹에서 "바로 채우기" 를 누르면 내 컴퓨터가 어드민의 그 리뷰 답글칸을 채우게 한다.
채우는 건 scripts/fill.ts 를 그대로 쓴다. 등록 버튼은 누르지 않는다.

- 웹은 인터넷 서버에 있어서 내 컴퓨터의 브라우저를 못 연다.
  내 컴퓨터에 작은 도우미 서버(scripts/agent-server.ts, localhost:4599)를 띄워.
  웹 버튼이 POST /fill {review_id} 를 보내면, 도우미가 DB 에서 그 리뷰의 단서와 초안을 꺼내
  scripts/fill.ts 를 한 번 실행한다.
- 웹이 https 이고 도우미가 localhost 라, 크롬은 사전 요청에
  Access-Control-Allow-Private-Network: true 를 요구한다. 이 헤더가 없으면 요청이 조용히 끊긴다.
- 도우미가 꺼져 있으면 웹은 "도우미를 켜고 다시 누르세요" 라고만 말해. 어드민 홈으로 보내지 마.
- 한 번에 한 건만. 채우는 중에는 다른 요청을 받지 마.
- 채운 뒤 "채운 답글 보러 가기" 버튼: 그 브라우저 창을 앞으로 가져온다.
- 단서: 배민은 리뷰번호, 네이버는 닉네임. 쿠팡은 이름을 가려서 보여주니
  가린 이름 · 리뷰 날짜 · "N회 주문" · 메뉴 앞부분이 모두 맞는 줄이 딱 하나일 때만. 둘 이상이면 멈춰.

먼저 한 플랫폼 한 건으로 끝까지 확인하고 멈춰서 나한테 보여줘. 여러 건 연속으로 돌리지 마.
```

**끝났는지 확인**: 웹에서 누름 → 브라우저 창에 그 리뷰 답글칸이 채워져 있음 → 등록은 안 눌림.
플랫폼마다 1건씩, **하루에 한 곳씩.**
