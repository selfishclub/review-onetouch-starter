# 리뷰 원터치 스타터 키트

배민 · 쿠팡이츠 · 네이버 리뷰를 한 화면에 모으고, 내 말투로 답글 초안을 쓰고,
승인하면 어드민 답글칸까지 채워주는 도구를 **Claude Code 와 함께 직접 만드는** 키트입니다.
등록 버튼은 언제나 사람이 누릅니다.

## 한 번에 다 만들지 않습니다 — 기획 → 세팅 → 단계별로

| 순서 | 하는 일 | 사장님이 하는 일 | 끝나면 남는 것 |
|---|---|---|---|
| **기획** | 내 가게 상황을 묻고 기획서를 씁니다. 설치 · 로그인은 아직 안 합니다 | 보기 고르기 · 최근 답글 3개 붙여넣기 | 기획서 `docs/PRD.md` |
| **세팅** | 기획서에 맞는 준비물만 설치하고 빈 화면을 띄웁니다 | 설치 창에서 확인 누르기 | 준비 확인 ✅ · 화면 뼈대 |
| **1단계** | 화면을 우리 가게에 맞춥니다 (가짜 리뷰로) | 화면 보고 고칠 곳 말하기 | 우리 가게용 화면 |
| **2단계** | 리뷰가 제일 많은 플랫폼 **한 곳**만 가져옵니다 | 그 플랫폼 로그인 한 번 | 내 가게 리뷰 파일 |
| **3단계** | 나머지 플랫폼 + 리뷰 창고 | 플랫폼마다 로그인 한 번 · 창고 가입 | 모든 리뷰가 한 화면에 |
| **4단계** | 내 말투로 답글 초안 | 초안 읽고 어색한 곳 말하기 | 「내가 쓴 것 같은」 초안 |
| **5단계** (선택) | 밤에 혼자 모으고 초안까지 | 밤에 컴퓨터 켜 두기 | 아침 알림 |
| **6단계** (선택) | 승인하면 어드민 답글칸까지 채우기 | 에이전트 브라우저 설치 · 로그인 | 답글칸이 채워짐 · 등록은 직접 |

- 단계마다 AI 가 **프롬프트를 먼저 보여 주고 「바로 실행할까요?」** 라고 묻습니다. 끝나면 **「끝났는지 확인」** 을 같이 보고 다음으로 갑니다.
- 어느 단계에서 멈춰도 됩니다. 진행 상황은 `docs/PROGRESS.md` 에 남아서, 다음에 **「리뷰 원터치 이어서 하자」** 라고 하면 그 자리부터 합니다.
- 기획서에서 고른 만큼만 갑니다. 4단계까지만 써도 충분히 쓸모 있습니다.

## 쓰는 법 — Claude Code 에 한마디

[Claude Code](https://claude.com/claude-code) 를 열고(데스크톱 앱의 Code 탭이면 터미널을 몰라도 됩니다) 이렇게 말하세요.

```
https://github.com/selfishclub/review-onetouch-starter 참고해서 우리 가게만의 리뷰 댓글 시스템 만들고 싶어
```

다음에 이어서 할 때는 Claude Code 에서 **`review-onetouch-starter` 폴더를 열고** 「리뷰 원터치 이어서 하자」 라고 하면 됩니다.

> 윈도우는 Claude Code 를 쓰려면 [Git for Windows](https://git-scm.com/downloads/win) 가 먼저 깔려 있어야 합니다.

> **이 저장소를 읽는 AI 에게 — 이 순서로 진행하세요**
> 사장님은 코딩을 모릅니다. **사장님께 터미널 명령을 시키지 말고 직접 실행하세요.** 설명을 늘어놓지 말고 진행 상황만 한 줄씩 알리세요.
> **한 번에 한 순서씩.** 기획 · 세팅 · 각 단계를 하나 끝낼 때마다 멈추고 다음으로 갈지 묻습니다. 여러 단계를 한꺼번에 하지 않습니다.
>
> 1. **키트만 먼저 받습니다.** `~/review-onetouch-starter` (홈 폴더. 이미 있으면 그대로 씁니다).
>    - 맥은 `xcode-select -p` 가 성공할 때만 git 을 씁니다. 실패하면 git 을 부르지 말고(1GB 넘는 설치 창이 뜹니다)
>      `https://github.com/selfishclub/review-onetouch-starter/archive/refs/heads/main.zip` 으로 받아 풉니다. 윈도우도 git 이 없으면 zip.
>    - 받은 뒤 **그 폴더의 `CLAUDE.md` 를 읽고 따릅니다.** (이 대화가 다른 폴더에서 시작됐으면 Claude Code 가 자동으로 읽지 않습니다)
>    - `docs/PROGRESS.md` 가 있으면 그 기록의 다음 순서부터 합니다.
>    - 이 단계에서는 Node · 부품 설치를 하지 않습니다. 세팅 순서에서 합니다.
> 2. **기획.** 아래 「기획 프롬프트」 를 **줄이거나 고치지 말고 원문 그대로** 코드 블록으로 보여 준 뒤
>    "이게 기획 프롬프트인데 바로 실행할까요?" 를 AskUserQuestion 으로 묻습니다 (바로 실행 / 고치고 싶은 곳이 있어요).
>    (가게 이름)은 실행 전에 물어 채웁니다. 실행하면 그 프롬프트를 사장님이 보낸 것처럼 따릅니다.
> 3. **세팅.** 기획서가 나오면 「세팅 프롬프트」 를 같은 방식으로 보여 주고 묻습니다.
> 4. **단계.** 세팅이 끝나면 「1단계」 프롬프트를 보여 주고 묻습니다. 한 단계가 끝나면 그 단계의 「끝났는지 확인」 을
>    사장님과 함께 보고, `docs/PROGRESS.md` 에 적고, 다음 단계 프롬프트를 보여 주고 다시 묻습니다.
>    기획서에서 「안 함」 으로 고른 단계는 건너뜁니다. 4단계가 끝나면 "며칠 초안을 읽어본 뒤 다음 단계로 가길 권합니다" 를 먼저 말합니다.
> 5. **명령을 실행할 수 없는 환경(일반 채팅)이면** 키트 받기 · 설치는 건너뛰고 "Claude Code 에서 같은 말을 해주세요" 한 줄로 안내합니다.
>    원하면 기획 질문과 기획서까지만 여기서 합니다.
> 6. 이 키트는 한 가게가 자기 컴퓨터에서 쓰는 도구입니다. 지킬 선은 [`CLAUDE.md`](CLAUDE.md) —
>    등록 버튼은 사람이, 로그인은 사람이 창에서, 플랫폼 접속은 한 번에 하나씩, 로그인은 그 플랫폼을 쓰는 단계에서.

## 기획 프롬프트 — 만들기 전에, 무엇을 어디까지

AI 가 내 상황을 묻고 기획서(`docs/PRD.md`)를 씁니다. **설치도, 로그인도, 플랫폼 접속도 아직 하지 않습니다.**
직접 붙여넣어도 됩니다 — (가게 이름)만 바꾸세요.

```
【 S · 상황 】
- 나는 (가게 이름) 사장이야. 배달앱 · 네이버에 리뷰가 흩어져 있고, 답글은 지금 내가 하나씩 달아.
- 리뷰 원터치 스타터 키트(https://github.com/selfishclub/review-onetouch-starter)로 내 가게용 리뷰 도구를 만들고 싶어.
- 나는 코딩을 잘 몰라. 터미널도 써본 적 없어.

【 T · 할 일 】
1. 내 상황을 AskUserQuestion 으로 물어봐 — 한 번에 1~4개, 번호 보기로 고를 수 있게.
   - 쓰는 플랫폼 · 맥/윈도우 · 플랫폼별 리뷰 양 · 지금 답글 다는 방식과 걸리는 시간
   - 목적 우선순위 (빠짐없이 답하기 / 리뷰를 데이터로 쓰기 / 시간 줄이기)
   - 밤에 컴퓨터를 켜 두는지 (5단계 밤 자동 실행이 되는지 정해진다)
   - 화면을 폰에서도 볼지, 가게 컴퓨터에서만 볼지 (인터넷에 올릴지 정해진다)
   - 어디까지 만들지 — README 의 1~6단계 중 목표 (처음엔 4단계까지를 권해줘)
   - 예산 (돈이 드는 건 따로 물어봐)
2. 내 말투를 알 수 있게 최근 답글 3개를 붙여 달라고 해. 절대 자동화하면 안 되는 것도 물어봐.
3. docs/PRD_TEMPLATE.md 틀로 docs/PRD.md 를 써줘. 「만들 단계」 표에 할 단계와 안 할 단계를 표시해줘.
4. 다 쓰면 기획서를 쉬운 말로 다섯 줄 안에 요약해서 보여주고, 다음은 세팅이라고 알려줘.

【 I · 의도 】
- 모은 고객이 떠나지 않게 빠짐없이 답하고, 리뷰를 데이터로 쓰고, 관리 시간을 줄이려는 거야.
- 가게마다 상황이 달라서, 만들기 전에 내 상황에 맞는 범위와 순서부터 정하고 싶어.

【 C · 주의할 점 】
- 이번엔 기획서까지만. 설치하지 말고, 구현하지 말고, 플랫폼에 접속하거나 로그인 창을 띄우지 마.
- 아이디 · 비밀번호는 묻지 마.
- 답글 등록 버튼은 내가 누른다. PRD 의 「안 만들 것」에 넣어줘.
- 모르는 건 지어내지 말고 「확인 필요」로.
```

**끝났는지 확인**: `docs/PRD.md` 가 생겼고, 요약 다섯 줄이 내 가게 이야기로 읽힌다. 「만들 단계」에 어디까지 할지 표시돼 있다.

## 세팅 프롬프트 — 기획서에 맞는 준비물만

```
【 세팅 — 준비물 설치와 화면 뼈대 】

docs/PRD.md 를 읽고, 거기 적힌 단계에 필요한 준비물만 챙겨줘. 명령은 네가 실행하고 결과만 쉬운 말로 알려줘.

1. 키트 폴더 위치 확인
   - 맥: 바탕화면 · 문서 · 다운로드 안이면 밤 예약 실행이 못 읽는다. 홈 폴더 바로 아래인지 확인해.
   - 윈도우: OneDrive 가 바탕화면 · 문서를 동기화하는 PC 면 그 안은 피해서 C:\Users\(이름)\ 바로 아래에.
2. Node.js LTS (20 이상). 없으면 설치해줘.
   - 맥: nodejs.org 설치 파일(.pkg)을 받아 열어줘. 내가 설치 창에서 「계속」만 누를게.
   - 윈도우: winget install OpenJS.NodeJS.LTS. 설치 뒤 이 창에서 npm 을 못 찾으면,
     나한테 「Claude Code 를 껐다 켜고 '리뷰 원터치 이어서 하자' 라고 해 주세요」 라고만 말해.
3. 키트 폴더에서 npm install → npx playwright install chromium → .env.local 이 없으면 .env.example 복사.
4. npm run check 로 확인. 「세팅 완료」 가 나오면 된다. 가게 번호 · 로그인 · 에이전트 브라우저는
   「다음 단계에서」 로 나오는 게 정상이니 지금 하지 마.
5. npm run dev 로 화면 뼈대(가짜 리뷰 5건)를 띄워서 주소를 알려줘. 내가 확인하면 서버를 꺼.

- 플랫폼 로그인 창은 아직 띄우지 마. 그 플랫폼을 가져오는 단계에서 한다.
- 에이전트 브라우저도 아직. 6단계를 할 때 설치한다.
- 설치 중 「critical」 같은 경고가 나와도 npm audit fix --force 는 하지 마. 버전이 통째로 바뀐다.
```

**끝났는지 확인**: `npm run check` 마지막 줄이 「세팅 완료」 이고, 브라우저에 가짜 리뷰 카드 5개가 뜬다.

## 단계 프롬프트 — 하나씩

- 앞 단계의 **끝났는지 확인**을 통과해야 다음으로 갑니다.
- 지킬 선(등록 금지 · 로그인은 사람이 · 읽기 전용 · 한 번에 하나씩)은 Claude Code 가 [`CLAUDE.md`](CLAUDE.md) 에서 매번 읽습니다.
- 아래는 배민 · 쿠팡이츠 · 네이버 예시입니다. 기획서에 다른 플랫폼이 나왔으면 이름을 바꿔서 시키세요.

### 1단계 — 화면을 우리 가게에 맞추기

실제 플랫폼에는 아직 접속하지 않습니다. 가짜 리뷰로 「매일 아침 볼 화면」 부터 정합니다.

```
【 1단계 — 우리 가게 화면 】

- docs/PRD.md 를 읽고 sample/reviews.json 을 우리 가게 메뉴 · 손님 말투와 비슷한 가짜 리뷰 10건으로 바꿔.
  내가 쓰는 플랫폼만, 별점 1~5 와 질문 리뷰 · 별점만 남긴 리뷰를 섞어서. 진짜 손님 이름은 쓰지 마.
- 화면에서 PRD 의 목적에 맞게 순서를 정해: 미답변이 먼저, 별점 낮은 리뷰가 눈에 띄게.
  안 쓰는 플랫폼 필터는 빼.
- 바꾸기 전에 화면을 어떻게 바꿀지 글로 먼저 보여주고, 내가 좋다고 하면 바꿔.
- 끝나면 npm run dev 로 띄워서 주소를 알려줘.
```

**끝났는지 확인**: 화면을 보고 「이걸 매일 아침 보면 되겠다」 싶다. 아니면 무엇이 불편한지 말하고 고칩니다.

### 2단계 — 첫 플랫폼 한 곳만 가져오기

세 곳을 한꺼번에 하지 않습니다. PRD 에서 **리뷰가 제일 많은 곳 하나**부터. 아래는 배민 예시입니다.
로그인은 **이 단계에서, 이 플랫폼만** 합니다.

```
【 2단계 — 첫 플랫폼 리뷰 가져오기 (배민) 】

준비:
- 배민 로그인 창을 띄워줘(npm run login -- baemin). 로그인은 내가 창에서 하고, 끝나면 알려줄게.
- 로그인한 화면에서 가게 번호를 찾아 .env.local 에 채워줘(npm run detect-ids). 못 읽으면 어드민 주소를 붙여 달라고 해.

가져오기 — 접속은 한 번, 개발은 저장한 파일로:
- scripts/collect-baemin.ts 를 만들어. scripts/lib/browser.ts 의 openPersistent 로
  배민 어드민 리뷰 페이지(scripts/platforms.ts 의 reviewsUrl)를 열고, enforceReadOnly 를 켜.
- 먼저 한 번만 열어서 어드민이 스스로 받아오는 응답을 data/capture/ 에 그대로 저장해.
  어떤 요청이 리뷰인지 저장한 파일을 보고 알아내서 나한테 설명해.
- 그다음 개발과 시험은 data/capture/ 의 저장 파일로만 해. 고칠 때마다 어드민에 다시 들어가지 마.
- 배민은 요청에 서명이 붙어서 우리가 새로 보내면 거절된다. 어드민이 보내는 요청의
  개수 · 쪽수 값만 바꿔치기해. 기간 값은 건드리지 마.
- 저장: data/baemin-reviews.json. 한 건에 플랫폼, 리뷰번호, 별점, 내용, 주문 메뉴,
  작성일, 작성자 표시명, 사장님 답글(있으면), 답글 작성일.
- 증분: INCREMENTAL=1 이면 저장된 것 이후 새 리뷰만.
- 다 되면 실제로 한 번 돌려서 확인해. 막히면 data/screenshots/ 에 스크린샷을 남기고 멈춰.
- 화면이 sample 대신 data/baemin-reviews.json 을 읽게 바꿔.
```

**끝났는지 확인**: 화면에 내 가게 배민 리뷰가 뜨고, 사장님 답글이 붙은 리뷰도 보인다.

### 3단계 — 나머지 플랫폼 + 리뷰 창고

2단계를 **플랫폼마다 한 번씩** 반복한 뒤, 모은 리뷰를 창고(DB)에 쌓습니다.

```
【 3단계 — 나머지 플랫폼 수집 + 리뷰 창고 】

2단계와 같은 순서로, 한 플랫폼씩. 로그인 창 → 가게 번호 → 한 번 저장 → 저장 파일로 개발 → 실제로 한 번.
한 플랫폼이 끝나면 나한테 보여주고 다음 플랫폼으로 갈지 물어봐.

쿠팡이츠 (scripts/collect-coupang.ts):
- 봇 차단이 강하다. 브라우저 밖에서 부르면 전부 막힌다. 어드민 페이지 안에서 같은 출처 fetch 로 불러.
- 한 번에 받는 개수를 바꾸면 거절될 수 있다. 어드민이 쓰는 값을 그대로 써.
- 로그인 성공은 매장 정보 API 가 정상 응답하는지로 판단해. 막혔으면
  "쿠팡이 이 브라우저를 막았다, 다시 로그인하라" 고 알리고 멈춰.

네이버 스마트플레이스 (scripts/collect-naver.ts):
- 로그인 창에서 보호조치가 잘 걸린다(docs/TOOLS.md). 로그인은 한 번만 띄우고,
  막히면 다시 시도하지 말고 멈춰서 알려줘. 다음 날 다시 한다.
- 방문자 리뷰다. 별점 없이 글만 있는 리뷰가 많다. 평균 계산에서 빼.
- 창 없는 모드를 봇으로 보니, 창을 화면 밖에 띄워(openPersistent 의 offscreen).
- 네이버는 조회도 POST(GraphQL)로 한다. enforceReadOnly 는 쓰기(mutation)가 아닌 조회만 통과시킨다.
  막힌 요청은 터미널에 ⛔ 로 찍힌다. 조회인데 막혔으면 알려줘.

리뷰 창고:
- 무료로 시작할 수 있는 Postgres 를 추천해줘. 가입과 연결 문자열 복사는 내가 할게.
  DATABASE_URL 은 .env.local 에만. 돈이 드는지 먼저 알려줘.
- 테이블: 리뷰 · 답글(초안) · 말투. 같은 플랫폼 + 리뷰번호는 덮어써서 몇 번 돌려도 중복이 안 쌓이게.
- scripts/ingest.ts: 수집 JSON 을 DB 에 넣는다. 리뷰 내용을 보고 불만 종류를 규칙으로 붙여
  (맛·품질 / 양·가격 / 배달·포장 / 응대 / 위생 / 기타). LLM 없이.
- 화면이 DB 를 읽게 바꿔.

PRD 에서 「폰에서도 본다」 를 골랐으면 (아니면 건너뛰어):
- 화면을 인터넷에 올리는 방법을 무료 플랜 기준으로 알려주고, 가입은 내가 할게.
- 손님 리뷰가 보이는 화면이니 올리기 전에 비밀번호를 꼭 걸어.
```

**끝났는지 확인**: 화면에 쓰는 플랫폼의 실제 리뷰가 모두 뜬다. 사장님이 예전에 단 답글이 창고에 수백 건 이상 있다.
이게 없으면 4단계가 의미가 없습니다 — **기존 답글이 곧 말투 교본**입니다.

### 4단계 — 내 말투로 초안

```
【 4단계 — 내 말투로 초안 쓰기 】

scripts/analyze-voice.ts:
- 플랫폼별로 내 기존 답글을 읽어 뽑아: 호칭(손님/고객님/OO님), 종결어미, 첫인사, 끝인사,
  평균 길이, 자주 쓰는 이모지, 자주 쓰는 문장(횟수 포함). DB 에 저장.

초안 조립:
- LLM 을 쓰지 말고, 말투 분석에서 나온 내 실제 문구를 재료로 조립해. 그래야 내 말 그대로 나온다.
- 리뷰 내용을 먼저 보고 손님이 무엇을 짚었는지 골라. 주문 메뉴로 먼저 맞추지 마.
- 홀과 배달을 구분해. 네이버는 방문 리뷰라 기본이 홀, 배달앱은 배달.
  다만 본문에 "매장 · 가서 · 방문" 이 있으면 홀, "배달 · 포장 · 시켰" 가 있으면 배달.
  방문 손님에게 배달 이야기가 나가면 안 된다.
- 손님이 질문했으면 그 자리를 비워둬: 【여기에 답을 적어주세요 — 손님이 물어본 내용입니다】
  지어내지 마.
- 별점 1~2점은 사과가 먼저다. 설명은 그다음. 불만이 없는 3점에 사과하지 마.
- 내가 알려주지 않은 가게 사실(재료 산지, 조리법 등)은 쓰지 마.

scripts/draft-all.ts: 답글 없는 리뷰 전부에 초안을 만든다. DB 에는 묶어서 넣어.
화면: 초안이 펼쳐져 보이고, 고칠 수 있고, "초안 다시 쓰기" 버튼이 있다.
```

**끝났는지 확인**: 초안 20건을 읽어보세요. "내가 쓴 것 같다" 싶으면 통과.
아니면 무엇이 어색한지 AI 에게 말해주세요. 여기서 며칠 써도 됩니다. **다음 단계는 며칠 써 본 뒤에** 가세요.

### 5단계 — 밤에 혼자 돌게 (선택)

PRD 에서 「밤에 컴퓨터를 켜 둔다」 를 골랐을 때만 합니다. 아니면 아침에 「오늘 리뷰 모아줘」 라고 한 번 시키면 됩니다.

```
【 5단계 — 밤 배치 】

scripts/auto-collect.ts:
- 플랫폼 수집을 차례로. 하나가 실패해도 나머지는 계속. 모두 실패하면 적재는 건너뛴다.
- 그다음 ingest → analyze-voice → draft-all.
- 새 리뷰만 받는다 (최근 14일 정도).
- 끝나면 알림을 한 번 띄워. 실패한 플랫폼이 있으면 "확인 필요 — OO 로그인이 풀렸을 수 있습니다".
  조용히 실패하면 나는 리뷰가 없는 줄 안다.
- 로그는 data/logs/ 에 날짜별로. 매 실행 결과(플랫폼, 성공 여부, 새 리뷰 수)를 DB 에도 남겨서
  화면에서 볼 수 있게.

예약 등록 — 내 컴퓨터(PRD 참고) 쪽만 만들어:
- 맥: launchd. 등록 전에 예약 실행이 이 폴더를 읽을 수 있는지 확인해.
  바탕화면 · 문서 · 다운로드 안이면 막힌다. 그러면 등록하지 말고 폴더를 옮기라고 안내해.
- 윈도우: 작업 스케줄러. 컴퓨터가 잠들어 있으면 못 도니 "절전 해제하여 실행" 을 켜.
- 하루 한 번이면 충분하다. 자주 돌리면 플랫폼이 막는다.
```

**끝났는지 확인**: 밤에 혼자 돌고, 아침에 알림이 와 있고, 화면에 새 리뷰와 초안이 있다.

### 6단계 — 승인하면 답글칸까지 (선택)

가장 위험한 단계입니다. 등록 버튼은 이 단계에서도 사람이 누릅니다.
채우는 코드는 **`scripts/fill.ts` 에 이미 있습니다.** 이 단계는 에이전트 브라우저를 준비하고, 화면의 승인 버튼과 이어붙이는 일입니다.

먼저 AI 에게 이렇게 말해 준비하고 한 건만 시험합니다.

> 에이전트 브라우저를 준비해줘(맥: ego lite 또는 Aside, 윈도우: Aside). 설치 페이지를 열어주면 내가 설치할게.
> 붙는지 확인(npm run fill -- --selftest)한 뒤, 그 브라우저 창에서 쓰는 플랫폼마다 한 번씩 로그인 창을 띄워줘.
> 그다음 최근 리뷰 한 건만 답글칸에 채워줘. 등록은 누르지 마.

그다음 시킵니다.

```
【 6단계 — 승인 → 어드민 답글칸 채우기 】

화면에서 "바로 채우기" 를 누르면 내 컴퓨터가 어드민의 그 리뷰 답글칸을 채우게 한다.
채우는 건 scripts/fill.ts 를 그대로 쓴다. 등록 버튼은 누르지 않는다.

- 화면이 내 컴퓨터에서만 돌면(npm run dev) 화면 서버가 바로 scripts/fill.ts 를 한 번 실행한다.
- 화면이 인터넷에 있으면 내 컴퓨터의 브라우저를 못 연다.
  내 컴퓨터에 작은 도우미 서버(scripts/agent-server.ts, localhost:4599)를 띄워.
  화면 버튼이 POST /fill {review_id} 를 보내면, 도우미가 DB 에서 그 리뷰의 단서와 초안을 꺼내
  scripts/fill.ts 를 한 번 실행한다.
  화면이 https 이고 도우미가 localhost 라, 크롬은 사전 요청에
  Access-Control-Allow-Private-Network: true 를 요구한다. 이 헤더가 없으면 요청이 조용히 끊긴다.
  도우미가 꺼져 있으면 화면은 "도우미를 켜고 다시 누르세요" 라고만 말해. 어드민 홈으로 보내지 마.
- 한 번에 한 건만. 채우는 중에는 다른 요청을 받지 마.
- 채운 뒤 "채운 답글 보러 가기" 버튼: 그 브라우저 창을 앞으로 가져온다.
- 단서: 배민은 리뷰번호. 네이버는 닉네임에 날짜 · 본문 앞부분을 --also 로 더 준다(같은 손님이 여러 번 쓴다).
  쿠팡은 이름을 가려서 보여주니 가린 이름 · 리뷰 날짜 · "N회 주문" · 메뉴 앞부분을 모두 단서로.
  fill.ts 는 단서가 모두 맞는 카드가 딱 하나일 때만 채우고, 둘 이상이면 멈춘다. 멈추면 단서를 더 줘.

먼저 한 플랫폼 한 건으로 끝까지 확인하고 멈춰서 나한테 보여줘. 여러 건 연속으로 돌리지 마.
```

**끝났는지 확인**: 화면에서 누름 → 브라우저 창에 그 리뷰 답글칸이 채워져 있음 → 등록은 안 눌림.
플랫폼마다 1건씩, **한 번에 한 곳씩.** 여러 곳을 동시에 돌리거나 연달아 다시 시도하지 않습니다.
